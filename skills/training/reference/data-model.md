# Data model

One folder per athlete: `athletes/<slug>/`. The slug is the URL (`/<slug>`) and the `--athlete`
argument of every tool. Lowercase, no spaces (`ana`, `juan-p`).

```
athletes/<slug>/
  config.json     schemaVersion, activeCycle, rules, zones, gear, tracked issues, locale, ingest, calendar
  sessions.json   everything ever done, across cycles, with the coach's feedback
  context.json    daily sleep, weight, resting HR, HRV, steps
  HANDOFF.md      everything an agent needs to coach this athlete (in their language)
  CLAUDE.md       optional: this athlete's own non-negotiable rules
  calendar.ics    generated by tools/gen-ics.py (every cycle)
  cycles/<id>/    one per goal; past cycles are kept exactly as they ended
    cycle.json    id, status, from, to, goal, result
    plan.json     phases, notes, weeks → days → workouts
    retro.md      written when the cycle closes (in the athlete's language)
```

The app shows the active cycle at `/<slug>`, any other at `/<slug>/<id>`, and a History tab
across all of them. `config.schemaVersion` is the data format (currently **2**); older data is
brought up with `python3 tools/migrate.py` (run by `/strata:upgrade`).

`tools/validate.py` checks all of this. The TypeScript types are in `src/lib.ts`.

## config.json

```jsonc
{
  "schemaVersion": 2,
  "activeCycle": "2027-media-bsas",
  "athlete": { "name": "Ana", "age": 34, "heightCm": 165, "weightKg": 61 },   // age/height/weight optional
  "schedule": {
    "days": ["tue", "thu", "sat"],                 // the run days the plan uses
    "available": {                                 // every day they could run → minutes that fit
      "mon": 45, "tue": 45, "wed": 30, "thu": 45, "sat": 120, "sun": 90
    },
    "preferred": ["tue", "thu", "sat"],            // what they'd rather do, before rules adjust it
    "longRunDay": "sat",                           // optional
    "notes": "Wednesdays only after 20:00",        // optional, constraints in their words
    "otherTraining": [{ "what": "Freeletics", "days": ["mon", "wed", "fri"], "intensity": "moderate" }]  // optional
  },
  "rules": {
    "noBackToBackRunDays": true,
    "hoursBetweenQualityAndLong": 48,
    "easyDayHrCap": 152,            // omit when there's no HR data yet
    "weeklyVolumeIncreasePct": 10,
    "repeatWeekIfSymptomEarlier": true
  },
  "zones": {                        // optional
    "lthr": 170,
    "note": "Estimated from max HR. Recalibrate with the week 6 test.",
    "easyZone": 2,                  // which hr zone is "easy" (its hrHigh is drawn on the HR chart)
    "hr":   [{ "zone": 1, "name": "Recovery", "hrLow": 0, "hrHigh": 137 }],
    "pace": [{ "zone": 1, "name": "Recovery", "pace": "7:30-8:00/km", "feel": "Could sing" }]
  },
  "cadence": { "base": 160, "target": 168, "reference": 175 },   // optional; hides the chart when absent
  "gear": { "trackShoes": true, "shoes": ["Pegasus 41"], "surfaces": ["Park loop"] },  // trackShoes false: not asked, not shown
  "tracked": [],                    // see tracked-issues.md
  "locale": { "tz": "America/Argentina/Buenos_Aires", "lang": "es-AR", "tone": "voseo" },  // dashboard labels: es* → Spanish, anything else → English
  "ingest": { "mode": "manual", "platform": "android", "source": "Garmin Forerunner 55 + Connect app" },  // platform "ios" | "android"   // mode "manual" | "hae" — see ingest.md
  "calendar": { "uidPrefix": "ana" } // never change once the athlete subscribed
}
```

`hr[i]` and `pace[i]` are shown side by side in the Notes tab, so keep them the same length and
order.

## cycles/{id}/cycle.json

```jsonc
{
  "id": "2027-media-bsas",             // same as the folder; the URL segment
  "status": "active",                  // "active" (exactly one, = config.activeCycle) | "completed" | "abandoned"
  "from": "2027-05-03", "to": "2027-08-22",   // first and last day of its plan (plan.py skeleton sets them)
  "goal": {
    "type": "race",                    // "race" | "distance" | "habit"
    "name": "Buenos Aires 21K",        // required for race
    "date": "2027-08-22",              // required for race; optional otherwise (countdown uses plan end)
    "time": "07:30", "place": "Palermo",
    "distanceKm": 21.1,
    "target": "Finish running",        // shown in the header
    "stretch": "Sub 2:15"
  },
  "result": { "time": "2:11:40", "summary": "Negative split, no knee pain" }   // set when it closes
}
```

Cycles never overlap. A closed cycle's plan and sessions are not edited afterwards.

## cycles/{id}/plan.json

```jsonc
{
  "phases": [{ "name": "Base", "from": 1, "to": 5, "focus": "Walk/run to 20 min continuous" }],
  "notes":  [{ "id": "why_walk_breaks", "title": "Why walk breaks", "body": "…" }],
  "weeks": [{
    "n": 1, "from": "2027-05-03", "to": "2027-05-09",
    "phase": "Base", "focus": "…", "deload": false,
    "plannedKm": 9.5, "hours": 1.9,            // derived: tools/plan.py derive
    "sessions": [ /* derived: one per run workout {date, name, type, km, min} */ ],
    "days": [{
      "date": "2027-05-04",
      "workouts": [{
        "sport": "run",                          // "run" | "strength" | "rest"
        "type": "endurance",                     // endurance | long | recovery | threshold | vo2max | race-pace | test | race | strength | rest
        "name": "Walk/run 6×(3′/2′)",
        "desc": "One line: what and why.",
        "detail": "Full prescription. See instrumentation.md for the format.",
        "km": 3.5, "min": 40, "zone": "Zone 1-2"
      }]
    }]
  }]
}
```

Note bodies are plain text in the athlete's language with a light grammar the Notes tab renders:
an ALL-CAPS first sentence is a headline, `LABEL: text` a subheading, `TERM = meaning -> action`
lines colored rows (VERDE/AMARILLO/ROJO or GREEN/YELLOW/RED), indented lines bullets, `->` an arrow,
CAPS WORDS bold. Blank lines separate blocks.

Weeks run Monday to Sunday with all 7 days present. `tools/plan.py skeleton` creates them empty.
`km`/`min` of a day are the source; `weeks[].sessions`, `plannedKm` and `hours` are derived — never
hand-edit them, run `tools/plan.py derive`. A workout with `type: "race"` becomes the race event
in the calendar.

## sessions.json

```jsonc
{ "sessions": [{
  "date": "2027-05-04", "cycle": "2027-media-bsas", "week": 1, "done": true,   // cycle/week null between cycles
  "type": "run",                 // "run" | "walk" — walks don't count as running volume
  "km": 3.6, "minutes": 41, "avgHr": 131, "maxHr": 149, "cadence": 166,
  "shoes": "Pegasus 41", "surface": "Park loop", "rpe": 4,
  "tracked": { "knee": { "present": true, "onsetMin": 28, "severity": 2 } },
  "pendingReport": true,         // written by an ingest tool; delete once the athlete reported
  "notes": "Full technical record, in the athlete's language.",
  "feedback": {
    "title": "Walk/run 6×(3′/2′)",
    "light": "ok",               // ok | warn | stop
    "verdict": "One line.",
    "table": [{ "what": "HR peak", "plan": "≤152", "actual": "149", "ok": true }],
    "matters": ["≤ 3 bullets"],                // ARRAY
    "whereYouAre": ["paragraph", "paragraph"], // ARRAY — a bare string blanks the dashboard
    "next": { "level": "good", "action": "progress", "why": "…" }   // good | tight | bad
  }
}]}
```

Sorted by date. `cycle` and `week` are the cycle and plan week the date falls in (`null` when the
date is outside every cycle — e.g. recovery weeks after a race). `tracked` has one key per
`config.tracked[].id`; with `pendingReport`, `present: false` means **not reported**.
Keys starting with `_` are free-form archival analysis the app ignores.

## context.json

```jsonc
{ "sleepTarget": 7,
  "days": [{ "date": "2027-05-04", "sleep": 6.4, "deepSleep": 0.9, "remSleep": 1.3,
             "weight": 64.2, "restingHr": 58, "hrv": 61.5, "steps": 9120, "vo2max": 41.2 }] }
```

Any field may be `null`. Sorted, one entry per date. Partial days (a morning export) store
`steps`, `restingHr` and `hrv` as `null`.
